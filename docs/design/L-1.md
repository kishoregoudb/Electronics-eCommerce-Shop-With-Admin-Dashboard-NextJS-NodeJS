# CP-D design note: L-1 API authentication and authorisation

Status: **draft, awaiting SME approval. No L-1 code written.** Depends on S-2 (done on its branch). `server/app.js` already exports the app (Phase 0).

## Options
| Option | How | Pros | Cons |
|--------|-----|------|------|
| A (recommended) | Express decodes the NextAuth session JWT cookie with `next-auth/jwt` `decode` and `NEXTAUTH_SECRET`; browser sends `credentials: "include"` | Smallest change; matches story design; keeps Express as policy point | Cookie shared across ports only on `localhost`; other envs need cookie-domain + SameSite decision; add `next-auth`, `dotenv` to `server/package.json` |
| B | Proxy all API calls through Next.js route handlers, which check the session and forward | No cross-origin cookie; one origin | Large rewrite of every call; Express stays open if reachable |
| C | Shared session store (DB/Redis) | Revocation | New infrastructure; replaces NextAuth JWT |

## Plan (option A)
- `server/middleware/auth.js`: `authenticate` (attach `req.user = { id, role }` from the verified token only), `requireAuth`, `requireAdmin`, `requireSelfOrAdmin(param)`. Expired/tampered/wrong-secret tokens -> treated as anonymous -> 401 on protected routes; non-admin on admin route -> 403. Request-body `role` is never read for privilege.
- Cookie names: `next-auth.session-token` and `__Secure-next-auth.session-token`.
- Access matrix exactly as in STORIES.md L-1 (public catalogue reads, `/health`, guest `POST /api/orders`; admin for catalogue writes, bulk upload, user creation, order list/update/delete; self-or-admin for users/orders/notifications). Written to `docs/AUTH.md` and tested one route per row.
- Server-component routes stay public: `/api/slugs`, `/api/images` GET, products, categories, search.
- `lib/api.ts` adds `credentials: "include"`. Mount guards per router after limiters, keeping the existing order.

## Questions for the SME
1. Option A, B or C? 2. Cookie domain / SameSite outside localhost. 3. Guest checkout stays? 4. Single workspace intended? If not, declare `next-auth`, `dotenv`, `express-rate-limit` in `server/package.json`. 5. Server-component calls that need identity later (none today).
- Known side effects: ad hoc scripts in `server/tests/` assume an open API and will break for protected routes. The access log records `/api/users/email/<email>` (from S-1 notes); switch lookups to id after auth.
