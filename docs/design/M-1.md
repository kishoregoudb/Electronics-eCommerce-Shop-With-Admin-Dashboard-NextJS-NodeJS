# CP-D design note: M-1 server-authoritative, atomic order creation

Status: **draft, awaiting SME approval. No M-1 code written.**

## Request and response
- `POST /api/orders` body: customer fields as today, plus `items: [{ productId: string, quantity: integer }]`. `userId` stays optional (guest checkout allowed; L-1 later replaces it with the verified token identity).
- Client-supplied `total` is ignored (not an error, so old clients keep working). Response 201: `{ id, orderNumber: id, total, message }`.
- Errors keep today's shape `{ error, details }`: 400 empty/invalid items, quantity not a positive integer or above max; 404 unknown product id; 409 duplicate or out-of-stock product (`inStock !== 1`).

## Computation and transaction
- Load products with one `findMany({ where: { id: { in: ids } } })`; total = sum of `price * quantity` in integer arithmetic (both `Int`). Total is the subtotal, as today; tax and shipping stay UI-only.
- Duplicate check (same email, same computed total, last 1 minute) runs on the computed total, before the write. Notification logic stays after the commit and cannot fail the order.
- Write with Prisma **nested create**: `customer_order.create({ data: { ..., total, products: { create: items } } })`. One statement, atomic. Alternative: interactive `$transaction(async tx => ...)`; heavier, only needed if stock decrement is added later. Recommend nested create.
- Duplicate lines for the same product are merged (quantities summed) before validation.

## Open decisions for the SME
1. Max quantity per line: proposed **10** (not settled; needs a business answer).
2. Should server own tax and shipping? Proposed: no, out of scope.
3. `/api/order-product`: keep, mark deprecated in a code comment. Switch its controller to `server/utills/db.js`.
4. Checkout page: sends one request, drops the `addOrderProduct` loop; error handling reused.
5. Tests: mocked Prisma; forged total, unknown product, out-of-stock, rollback (nested create rejects -> no rows), quantity limits, duplicate, happy path.
