# CP-D design note: L-2 wishlist rebuild

Status: **draft, awaiting SME approval. No L-2 code written.** Branches from L-1 (not started), because the user id must come from the verified token.

## API (all require auth; user id from token only)
- `GET /api/wishlist` -> items with product (id, title, price, mainImage, slug, inStock).
- `POST /api/wishlist` `{ productId }` -> idempotent add; 404 if product missing; 200/201 with the item.
- `DELETE /api/wishlist/:productId` -> remove; 204.
- Remove the old `/:userId` shapes in `server/routes/wishlist.js`; create `server/controllers/wishlist.js`; mount router in `server/app.js`.

## Duplicates
Recommend **code-level check** (`findFirst` then create, inside the handler) for this story: no migration, no change to the two schemas (RF6). Residual race: two simultaneous adds can create two rows. Alternative: `@@unique([userId, productId])` in both schemas + migration from the root; stronger, but needs SME decision on schema ownership and cleanup of existing duplicates.
