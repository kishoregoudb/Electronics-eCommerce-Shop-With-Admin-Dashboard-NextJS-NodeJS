# Review pack: S-2 Accept only valid roles when creating or updating users

## 1. Summary
- `createUser` and `updateUser` now reject any role other than `user` or `admin` with 400. Allowed roles and default live once in `server/utills/roles.js`. Missing role: create defaults to `user`, update leaves role unchanged.
- **This story does NOT stop an anonymous caller from setting `admin`; L-1 does that.**
- Branch: `story/S-2-validate-user-roles`. Red flags: RF2 (part).

## 2. Acceptance criteria evidence
| Criterion | Evidence |
|-----------|----------|
| Roles exactly user/admin, one constant | `ALLOWED_ROLES` in `server/utills/roles.js` |
| Create invalid -> 400; missing -> user | `users.roles.test.js`: `rejects invalid role ... with 400 and no write`, `defaults to user when role is missing` |
| Update invalid -> 400; missing unchanged | `rejects invalid role`, `leaves role unchanged when missing` |
| Admin screens | Both screens use a `<select>` with only `admin` and `user` (new: default `user`; edit: loads current role). Verified by reading code, not in a browser (no DB). |
| Email, password >= 8, bcrypt 14 unchanged | Code untouched; test `keeps existing validation` |

## 3. Files changed
- `server/utills/roles.js` (new), `server/controllers/users.js`, `server/__tests__/users.roles.test.js` (new).

## 4. Tests
- 16 new tests pass. Case sensitivity decided: exact lowercase only (`Admin`, `ADMIN` rejected). Empty string, numbers, objects, arrays rejected on create and update.
