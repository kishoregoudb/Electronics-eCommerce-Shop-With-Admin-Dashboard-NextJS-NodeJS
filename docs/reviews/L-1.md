# Review pack: L-1 API authentication and authorisation

## 1. Summary
Express decrypts the NextAuth session cookie and applies the access matrix in `docs/AUTH.md`. The browser client sends the cookie. Red flags: RF1, RF2, RF9, RF10, RF14.

## 2. Acceptance criteria evidence
| Criterion | Evidence |
|-----------|----------|

| Expired, tampered, wrong secret rejected | `auth.test.js` |

| Public category read stays open | `auth.test.js` |

## 5. How to verify by hand
Sign in as admin and open an admin screen. The API calls need the session cookie. This was not clicked through: there is no database and no admin user.

## 6. Decisions marked Needs SME
Option A (verify the NextAuth JWT in Express) was implemented. Cookie domain outside localhost, guest checkout (kept), and declaring `next-auth` in `server/package.json` still need the SME. The package resolves from the root `node_modules` today.

## 7. AI usage notes
An expired-token test used `maxAge: -10`. `jwtDecrypt` allows 15 seconds of clock skew, so that token was accepted. The test now uses `-120`, and the middleware also rejects `exp` older than that skew.
