# Review pack: M-1 Make order creation server-authoritative and atomic

## 1. Summary
Checkout sends one request with `items`. The server loads prices, ignores a client `total`, and writes the order and its lines in one Prisma nested create. Branch: combined into the `main` working tree so the running app includes every story. Red flags: RF3, RF4, RF11.

## 2. Acceptance criteria evidence
| Criterion | Evidence |
|-----------|----------|
| Stored total is database price times quantity | `orders.pricing.test.js` forged total |
| Unknown product creates no order | same file, 404 |
| Out of stock creates no order | same file, 409 |
| Failed line write leaves no separate item insert | same file, nested `create` rejects, `customer_order_product.create` not called |
| Quantity 1 to 10 | same file |
| Response includes id and total | same file |
| Duplicate check remains | same file |
| Checkout uses one request | `app/checkout/page.tsx` no longer calls `/api/order-product` |
| Shared Prisma client | `customer_order_product.js` requires `server/utills/db.js` |

## 3. Files changed
Order controller, validation, checkout page, order-product controller, pricing tests.

## 4. Tests
`server/__tests__/orders.pricing.test.js` and the updated logging test. `npm test` is the check.

## 5. How to verify by hand
Needs MySQL, which is not running on this machine. With a seeded database: add two products to the cart, check out, and confirm the stored total matches database prices.

## 6. Decisions marked Needs SME
Max quantity 10. Nested create. Client total ignored. `/api/order-product` kept and marked deprecated. Tax and shipping stay in the UI.

## 7. AI usage notes
The first pricing fixtures used country `UK`, which the existing address validator rejects (minimum 5 characters). The 400 responses caught it.
