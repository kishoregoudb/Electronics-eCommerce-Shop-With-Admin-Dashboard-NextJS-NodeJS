# Review pack: L-2 Rebuild the wishlist

## 1. Summary
Signed-in shoppers can list, add, and remove wishlist items. The user id comes from the verified token. The product page has a heart toggle, `/wishlist` lists items, and the header count uses the same store. Red flags: RF8, RF6, RF1.

## 2. Acceptance criteria evidence
| Criterion | Evidence |
|-----------|----------|
| Endpoints require a session | `wishlist.test.js` anonymous 401 |
| A user cannot query another user's rows by id | list query is `where: { userId }` from the token |
| Duplicate add keeps one row | `wishlist.test.js` second POST returns 200 and does not create |
| Unknown product is 404 | `wishlist.test.js` |
| Header count | `wishlistStore.test.ts` updates `wishQuantity` after add and remove |
| Page and button | `app/wishlist/page.tsx`, `AddToWishlistBtn.tsx`, `WishItem.tsx` |

## 3. Files changed
New controller, route, page, button, row. Header and wishlist module fetch `GET /api/wishlist`. Store quantity bug fixed. Server Action `deleteWishItem` now throws, because it cannot send the session cookie.

## 4. Tests
`server/__tests__/wishlist.test.js` and `__tests__/web/wishlistStore.test.ts`.

## 5. How to verify by hand
Sign in, open a product, choose Add to wishlist, open the heart, remove the row. Blocked here: no MySQL and no user.

## 6. Decisions marked Needs SME
Duplicates are prevented in code, not with a database unique constraint. Mutations are client `apiClient` calls. A wishlist rate limiter of 20 per 5 minutes was added. Cascade delete was not re-checked against a database.

## 7. AI usage notes
The old wishlist route imported a controller that did not exist. Replacing that file was required before the API could boot.

## 8. SME verdict
Not reviewed. L-2 was built on the same working tree as L-1, not on a separate reviewed L-1 branch.
