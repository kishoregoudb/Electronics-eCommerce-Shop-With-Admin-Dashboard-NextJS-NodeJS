# Red flags register

Known problem areas in this repository, with evidence. Evidence was checked at handover; if a line moved, search for the quoted text.

| ID | Area | What we found (evidence) | Story | Ask the SME |
|----|------|--------------------------|-------|-------------|
| RF1 | No API authentication or authorisation | `server/app.js` mounts 12 routers and none of `server/routes/*.js` checks identity. `middleware.ts` guards only `/admin/:path*` pages. `GET /api/orders` (`server/routes/customer_orders.js`) returns every customer's order to any caller. | L-1 | Which pattern should the API use to verify the session? |
| RF2 | Role taken from the request body | `server/controllers/users.js`: `createUser` reads `role` (line 20, used line 44); `updateUser` reads it (line 53) and applies it (lines 84-85). | S-2, L-1 | Should roles be a Prisma enum rather than a free string? |
| RF3 | Order total trusted from the browser | `app/checkout/page.tsx` sends `total` from the Zustand cart. `server/utills/validation.js` `validateTotal` only range-checks it. `server/controllers/customer_orders.js` stores `validatedData.total`. | M-1 | Is the stored total meant to be the subtotal? The UI adds tax (total / 5) and shipping (5) for display only. |
| RF4 | Order creation is not atomic | Checkout posts the order to `/api/orders`, then each line item to `/api/order-product`. A failure part-way leaves a partial order. | M-1 | Interactive transaction or nested create? |
| RF5 | Personal data in logs | `server/controllers/customer_orders.js:9` logs the whole request body; the file has about 23 `console.log` calls. `app/checkout/page.tsx` logs order data to the browser console. The access log records URLs such as `/api/users/email/<email>`. | S-1 | Is there an approved logging and redaction standard? |
| RF6 | Two Prisma schemas, one shared client | `prisma/schema.prisma` and `server/prisma/schema.prisma` are identical today. `server/utills/db.js` loads the client generated from the root. `server/prisma/migrations/` holds only `migration_lock.toml`. README step 10 runs `prisma migrate dev` from `server/`. | any schema change | Which schema is canonical, and where do migrations live? |
| RF7 | Hardcoded API address | `app/(dashboard)/admin/bulk-upload/page.tsx:98`, `components/BulkUploadHistory.tsx:54` and `:84` call `http://localhost:3001`. `lib/config.ts` already reads `NEXT_PUBLIC_API_BASE_URL`. | XS-1 | How should server components reach the API: public or internal URL? |
| RF8 | Half-removed features and broken imports | `components/ProductTabs.tsx` imports `./RatingPercentElement` and `./SingleReview` (files do not exist). `components/modules/wishlist/index.tsx` imports `@/components/WishItem` (does not exist). `components/index.ts` has `AddToWishlistBtn` commented out. `server/routes/wishlist.js` requires `server/controllers/wishlist.js`, which does not exist, and the router mount in `server/app.js` is commented out. `components/Header.tsx` returns early near line 53 ("temporary disable wishlist fetching"). `HeartElement` links to `/wishlist` but `app/wishlist/` does not exist. | M-2, L-2 | Was the wishlist parked on purpose? Is there a reviews plan? |
| RF9 | No automated tests, app not testable | Root `package.json` has no test script. `server/package.json` has the npm placeholder. `server/tests/` holds ad hoc scripts. `server/app.js` calls `app.listen` on import and exports nothing. | Phase 0, L-1 | Preferred test runner and layout? |
| RF10 | Two paths to the database | NextAuth `authorize` (`app/api/auth/[...nextauth]/route.ts`) and `app/api/register/route.ts` use Prisma inside Next.js. Everything else goes through Express. | L-1 | Is that intended? |
| RF11 | Several Prisma clients | `server/controllers/customer_order_product.js`, `server/utills/validation.js` and `server/createAdminUser.js` call `new PrismaClient()` instead of using `server/utills/db.js`. | M-1 | Should there be one shared client? |
| RF12 | Hardcoded product-page values | `app/product/[productSlug]/page.tsx:75` passes `stock={94}`; line 80 shows SKU `abccd-18`; `components/ProductTabs.tsx:75` lists fixed colours. `Product` has only `inStock Int`, no SKU or colour. | M-2 | What SKU convention applies? |
| RF13 | Documentation differs from code | `/rate-limit-info` in `server/app.js` claims 5 login attempts per 15 minutes plus wishlist and product limits. `authLimiter` in `server/middleware/rateLimiter.js` allows 300 and no wishlist or product limiter exists. | note only | Which is the intended policy? |
| RF14 | Undeclared server dependencies | `server/package.json` omits `express-rate-limit` (declared only in the root) and `dotenv` (declared nowhere). `next-auth` is root-only. The server works because Node resolves up to the root `node_modules`. | L-1 | Is a single workspace intended? |
